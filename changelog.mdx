## Documentation updates

Track updates and changes to the Zeta · Synthetic Warehouse documentation.

<Update label="2026-10-12" description="Development environment & configurable fixtures" tags={["feature","release"]}>
  ## What changed

  ### New features

  - **Development environment** — A separate Development build is now available alongside the Standard build. Development builds use a separate persistent data root (`Development-v1`), display a visible Development badge and window title, and support a configurable fixture set through `development.json`.
  - **Development configuration file** — Development builds read a `development.json` file placed beside the executable. The file configures shop movement settings (`walkSpeed`, `arrivalIntervalSeconds`), development products with marketplace item/model mappings, synthetic stock quantities, and observed orders. Schema validation enforces size limits, naming conventions (`DEMO-` prefix), and supported order statuses.
  - **Settings editor for development configuration** — Development builds add a Development configuration section to the Settings screen with a JSON editor, save, reload, and **Create missing fixture entities** actions. Saving validates before replacing the existing file.
  - **Additive fixture creation** — Development fixtures are created additively and are replay-safe: existing products, orders, thresholds, and stock are preserved. Increasing stock adds only previously unseen units; decreasing does not delete. Consumed or exposed units are not replenished.
  - **Configurable Shop movement** — In Development builds, customer walk speed and arrival interval are configurable. These settings are presentation-only and do not affect fulfillment, inventory, or order processing.
  - **New command-line options** — `--development` enables the Development environment for editor runs. `--expect-development` and `--expect-standard` assert the build environment at startup.
  - **Development packaging** — A separate `windows-x64-development` artifact is produced with its own Godot export preset, output directory, and archive name. Development packages include `development.json` and `DEVELOPMENT.md`.

  ### Updated pages

  - [Configuration](/reference/configuration) — Development export preset, data path, CLI options, and full `development.json` schema reference
  - [Persistence](/architecture/persistence) — Development data directory
  - [Shop View](/workflows/shop-view) — Configurable movement in Development builds
  - [Quickstart](/quickstart) — Development package, data path, and new CLI options
</Update>

<Update label="2026-01-27" description="Shop Workspace & Visual Order Queues" tags={["feature"]}>
  ## What changed

  ### New features

  - **Shop workspace** — A new visual storefront where synthetic orders appear as arriving customers. Switch between Management, Warehouse, and Shop using the view buttons or the **F2** key. Your last selected view is saved between sessions.
  - **Order queue and waiting area** — Orders are split into a main queue (paid, ready to ship) and a separate waiting/review area (unpaid, unsupported, held, or blocked). Each customer shows its real status so you can see exactly what needs attention.
  - **Reduced-motion mode** — New accessibility setting that skips walking and departure animations, placing customers directly in position while keeping all order controls available.

  ### Updates

  - **F2 now cycles three views** — Management, Warehouse, and Shop.
  - **Command-line preview** — Use `--demo-preview --view=Shop` to launch directly into the Shop.
  - **Queue capacity and overflow** — The Shop shows up to 40 main-queue and 20 waiting-area customers, with exact overflow counts so totals are always visible.

  ### Learn more

  - [Quickstart](/quickstart) — Getting started with workspace views
  - [Order Processing](/workflows/order-processing) — How orders move through the system
  - [Warehouse View](/workflows/warehouse-view) — The existing warehouse workspace
</Update>

<Update label="2026-02-03" description="Windows x64 executable downloads" tags={["new feature","release"]}>
  ## New features

  **Windows x64 executable packages** — Zeta is now available as a downloadable Windows x64 ZIP package. You no longer need to build from source or install the .NET SDK, Godot, or a database server.

  - Download the ZIP, extract the complete folder, and run `Zeta.exe`.
  - The package bundles the .NET runtime, SQLite, and all Godot resources — no additional setup required.
  - Packages are published as GitHub prereleases when a version tag is pushed.

  See the [Quickstart](/quickstart) guide for getting started.
</Update>
