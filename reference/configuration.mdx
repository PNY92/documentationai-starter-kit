## Configuration

Find all Zeta configuration options across the .NET build, Godot project, Windows export, runtime preferences, command-line interface, and operational limits.

## .NET SDK

Zeta uses .NET SDK `10.0.401` and targets `net10.0`.

### SDK selection

`global.json` pins the SDK and prevents automatic roll-forward to another installed SDK version.

```json
{
  "sdk": {
    "version": "10.0.401",
    "rollForward": "disable"
  }
}
```

<ParamField body="sdk.version" param-type="string" show-location="false" required="true">The required .NET SDK version: `10.0.401`.</ParamField>

<ParamField body="sdk.rollForward" param-type="string" show-location="false" required="true">Disables SDK roll-forward. The build fails if SDK `10.0.401` is not available.</ParamField>

### Shared build properties

`Directory.Build.props` applies these settings to the projects in the repository.

<ParamField body="TargetFramework" param-type="string" show-location="false" required="true">Targets .NET `net10.0`.</ParamField>

<ParamField body="Nullable" param-type="string" show-location="false" required="true">Enables nullable reference types.</ParamField>

<ParamField body="ImplicitUsings" param-type="string" show-location="false" required="true">Enables implicit global using directives.</ParamField>

<ParamField body="LangVersion" param-type="string" show-location="false" required="true">Uses the latest available C# language version.</ParamField>

<ParamField body="Deterministic" param-type="boolean" show-location="false" required="true">Enables deterministic builds.</ParamField>

<ParamField body="RestorePackagesWithLockFile" param-type="boolean" show-location="false" required="true">Enables NuGet lock files for repeatable package restores.</ParamField>

<ParamField body="Configuration" param-type="string" show-location="false" required="true">Defaults builds to `Debug` unless another configuration is specified.</ParamField>

<ParamField body="RuntimeIdentifierGraphPath" param-type="string" show-location="false">Uses `portable` in runtime identifier lock names when no runtime identifier is supplied.</ParamField>

<ParamField body="ZetaLockRuntime" param-type="string" show-location="false">When set explicitly, overrides the inferred runtime identifier for locked dependency restores. The export script uses `win-x64` to restore the correct Windows export dependencies.</ParamField>

## Godot project

Zeta uses a Windows-oriented Godot .NET project with a desktop management layout.

<ParamField body="Godot version" param-type="string" show-location="false" required="true">Uses Godot `4.7` with C# support.</ParamField>

<ParamField body="Renderer" param-type="string" show-location="false" required="true">Uses the `GL Compatibility` renderer.</ParamField>

<ParamField body="Main scene" param-type="string" show-location="false" required="true">Starts from `Main.tscn`.</ParamField>

<ParamField body="Viewport size" param-type="string" show-location="false" required="true">Sets the project viewport to `1440x900`.</ParamField>

<ParamField body="Window override size" param-type="string" show-location="false" required="true">Uses `1366x850` as the desktop window override size.</ParamField>

<ParamField body="Minimum window size" param-type="string" show-location="false" required="true">Prevents the window from shrinking below `1100x700`.</ParamField>

<ParamField body="Stretch mode" param-type="string" show-location="false" required="true">Uses `canvas-item` stretching for the application layout.</ParamField>

<ParamField body="Default clear color" param-type="string" show-location="false" required="true">Uses a dark clear color for the project background.</ParamField>

## Export configuration

The export preset produces an unsigned Windows x86_64 build.

<ParamField body="Platform" param-type="string" show-location="false" required="true">Exports for Windows Desktop on `x86_64`.</ParamField>

<ParamField body="Resource mode" param-type="string" show-location="false" required="true">Includes all project resources in the export.</ParamField>

<ParamField body="Signing" param-type="string" show-location="false" required="true">Produces an unsigned executable.</ParamField>

<ParamField body="Embedded PCK" param-type="boolean" show-location="false" required="true">Disables the embedded PCK. The export keeps the PCK separate from the executable.</ParamField>

<ParamField body="Excluded files" param-type="string" show-location="false" required="true">Excludes build output and lock files from the exported resources.</ParamField>

<ParamField body="Texture compression" param-type="string" show-location="false" required="true">Uses S3TC and BPTC texture compression.</ParamField>

<ParamField body="Debug symbols" param-type="boolean" show-location="false" required="true">Does not include debug symbols.</ParamField>

<ParamField body="Output path" param-type="string" show-location="false" required="true">Writes the executable to `artifacts/windows/Zeta.exe`.</ParamField>

### Development export preset

<ParamField body="Development preset" param-type="string" show-location="false" required="true">Exports a separate **Windows Development** build using the `zeta_development` Godot feature tag. Development packages are written to `artifacts/windows-development/Zeta.exe` and include `development.json` and `DEVELOPMENT.md` alongside the executable.</ParamField>

<ParamField body="Development archive" param-type="string" show-location="false" required="true">Development packages are archived as `Zeta-<version>-windows-x64-development.zip` under `artifacts/release-development`.</ParamField>

<Callout kind="info">

The Standard and Development builds use separate Godot export presets, output directories, and archive names. Version-tag releases publish the Standard package. Development packages are built separately.

</Callout>

<Callout kind="info">

The export script restores the Windows x64 export dependencies in locked mode before performing the Godot export. This ensures the correct native dependencies (including `e_sqlite3.dll`) are copied into the export output. Do not bypass locked mode during export.

</Callout>

## Application preferences

Zeta stores preferences at `%LOCALAPPDATA%\Zeta\Synthetic-v1\preferences.cfg`.

<Callout kind="info">

Development builds use a separate data root at `%LOCALAPPDATA%\Zeta\Development-v1`. The Development directory holds its own database, DPAPI keys, preferences, and backups — entirely isolated from the Standard workspace.

</Callout>

<ParamField body="Workspace view" param-type="string" show-location="false" required="true">Selects the Management, Warehouse, or Shop view as the preferred workspace.</ParamField>

<ParamField body="Reduced motion" param-type="boolean" show-location="false" required="true">Reduces motion effects in the application interface.</ParamField>

<ParamField body="Font scale" param-type="string" show-location="false" required="true">Selects a font scale of `100%`, `150%`, or `200%`.</ParamField>

## Command-line options

Pass command-line options after the Godot project arguments.

| Option | Description |
| --- | --- |
| `--smoke-test` | Runs the isolated end-to-end smoke test, prints `ZETA_SMOKE_OK` on success, and exits. |
| `--demo-preview` | Starts an isolated workspace for visual inspection. |
| `--view=Warehouse\|Shop\|Inventory\|Settings\|History` | Opens the application at the selected view. |
| `--screenshot=<path>` | Captures a screenshot at the specified path. |
| `--development` | Enables the Development environment for editor or source runs. Exported executables are already configured for their build environment and cannot switch at runtime. |
| `--expect-development` | Asserts that the running build is a Development build. Fails startup if the build does not match. |
| `--expect-standard` | Asserts that the running build is a Standard build. Fails startup if the build does not match. |

<Callout kind="tip">

`--smoke-test` and `--demo-preview` create isolated temporary workspaces. They do not use the normal persistent workspace under `%LOCALAPPDATA%\Zeta\Synthetic-v1`.

</Callout>

## Development configuration

Development builds read a `development.json` file placed beside the executable. The file configures shop movement settings, development products with marketplace item/model mappings, synthetic stock quantities, and observed orders. Edit it through the Settings screen or edit the file directly and reload.

### Schema fields

<ParamField body="schemaVersion" param-type="string" show-location="false" required="true">Must be `1`.</ParamField>

<ParamField body="shop.walkSpeed" param-type="number" show-location="false" required="true">Customer walk speed. Range: `0.1`–`20`.</ParamField>

<ParamField body="shop.arrivalIntervalSeconds" param-type="number" show-location="false" required="true">Seconds between customer arrivals. Range: `0.1`–`30`.</ParamField>

### Validation rules

<Callout kind="alert">

- Maximum `200` products and `200` orders.
- Maximum `10,000` total configured stock units.
- Product thresholds and quantities are bounded to `10,000`.
- Order line quantities range from `1` to `10,000`.
- Product names, identifiers, order IDs, and recipients must begin with `DEMO-`.
- Identifiers must be `6`–`80` characters with no control characters.
- Supported order statuses: `READY_TO_SHIP`, `UNPAID`, `COMPLETED`, `CANCELLED`.
- Unknown JSON properties are rejected.
- Comments and trailing commas are accepted.
- Files over `1 MB` are rejected.
- Invalid JSON, unsupported schema versions, and invalid values are rejected.

</Callout>

### Fixture creation

<Callout kind="info">

- Fixture creation is additive and replay-safe: existing products and orders are preserved.
- Existing product thresholds are preserved.
- Increasing stock adds only previously unseen units; decreasing stock does not delete existing units.
- Consumed or exposed units are not replenished.
- Existing order facts and versions are not overwritten.
- Removing an entry from the configuration does not delete the entity.
- Fixture creation does not reserve, approve, deliver, or award XP.

</Callout>

### Settings editor

Development builds add a Development configuration section to the Settings screen with a JSON editor, **Save development configuration**, **Reload development configuration**, and **Create missing fixture entities**. Saving validates the candidate configuration before replacing the existing file. Reloading reads external edits. Invalid edits leave the previous saved configuration intact. Shop movement changes apply when opening the Shop view.

<Callout kind="alert">

Movement settings (`walkSpeed` and `arrivalIntervalSeconds`) are presentation-only. They do not change fulfillment capacity, inventory quantities, priority, queue limits, order state transitions, stock allocation, or delivery behavior.

</Callout>

## Operational limits

These limits are fixed prototype settings.

| Setting | Limit |
| --- | --- |
| Maximum products | `200` |
| Maximum import size | `10 MB` |
| Maximum import rows | `10,000` |
| Maximum valid preview page | `50` rows |
| Maximum visible warehouse shelves | `50` |
| Maximum visible warehouse orders | `100` total, with `25` per processing stage |
| Maximum reservation batch | `100` orders |
| Order freshness limit | `60` seconds |
| Reader concurrency | `4` readers |
| Writer acquisition timeout | `5` seconds |
| SQLite command timeout | `5` seconds |
| Automatic backup interval | `15` minutes of unlocked changed operation |
| Available-stock expiration interval | `30` seconds |
| Clipboard cleanup delay | `30` seconds |
| Shutdown wait budget | `5` seconds |

These limits are hard-coded in the prototype and cannot be changed without modifying the application source.
