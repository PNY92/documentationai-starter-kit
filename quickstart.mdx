## Set up and run Zeta

Set up and run the Zeta Synthetic Warehouse prototype on Windows, then verify the complete application flow with an isolated smoke test.

## Download a pre-built package

If you only need to run the prototype, download a self-contained Windows package from GitHub Releases instead of building from source:

1. Go to the [Zeta releases page](https://github.com/PNY92/zeta/releases) and download the latest `Zeta-<tag>-windows-x64.zip` file.
2. Extract **all files** from the ZIP archive.
3. Run `Zeta.exe`.

The package includes the .NET runtime, SQLite native dependencies, and all Godot resources. You do not need to install the .NET SDK, Godot, or a database server separately.

<Callout kind="info" collapsed="false">
  The package is an unsigned synthetic prototype. Windows SmartScreen may display a warning because the executable is not code-signed. Review the release notes before proceeding.
</Callout>

## Prerequisites

<Callout kind="info" collapsed="false">
  Install the following before you begin:

  - .NET SDK `10.0.401`
  - Godot `4.7.2` with .NET support
  - Windows 10 or Windows 11
  - Git

  Zeta is a Windows-first application. Normal execution is rejected on non-Windows platforms.
</Callout>

## Set up the project

<Steps>
  <Step title="Clone the repository" icon="download" title-type="h3">
    Clone the repository into a local working directory, then open a terminal at the repository root.
  </Step>

  <Step title="Restore dependencies" icon="package" title-type="h3">
    Restore the locked dependency set:

    ```powershell
    dotnet restore Zeta.slnx --locked-mode
    ```

    The restore completes without changing the locked dependency versions.
  </Step>

  <Step title="Build the solution" icon="code" title-type="h3">
    Build the solution with a single MSBuild worker:

    ```powershell
    dotnet build Zeta.slnx --no-restore -m:1
    ```

    A successful build produces the compiled .NET projects without restoring dependencies again.
  </Step>

  <Step title="Run the tests" icon="check-circle" title-type="h3">
    Run the integration and integrity test suite:

    ```powershell
    dotnet test tests/Zeta.Tests/Zeta.Tests.csproj --no-build --no-restore
    ```

    The tests use temporary SQLite stores and ephemeral encryption keys. A successful run reports that all tests passed.
  </Step>

  <Step title="Launch the Godot application" icon="play-circle" title-type="h3">
    Start the application from the repository root:

    ```powershell
    Godot --path src/Zeta.Godot
    ```

    You can also open `src/Zeta.Godot` in the Godot editor and run the project from there. The application creates its local synthetic workspace on first startup and seeds demo products, stock, and orders when the store is empty.
  </Step>

  <Step title="Run a smoke test" icon="terminal" title-type="h3">
    Run the end-to-end validation flow without opening the interactive application:

    ```powershell
    godot --headless --path src/Zeta.Godot -- --smoke-test
    ```

    Confirm that the process prints `ZETA_SMOKE_OK` before it exits.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  The `--smoke-test` option creates an isolated temporary workspace, runs a real end-to-end flow, creates an encrypted snapshot, prints `ZETA_SMOKE_OK`, and exits. It does not modify your normal workspace under `%LOCALAPPDATA%\Zeta\Synthetic-v1`.
</Callout>

<Callout kind="alert" collapsed="false">
  Normal execution is rejected on non-Windows platforms. The `--smoke-test` and `--demo-preview` options work cross-platform by using isolated temporary workspaces.
</Callout>

## Use the application

After you launch the app, it creates three synthetic products, twelve units per product, and eight demonstration orders on first startup. You have a working workspace immediately.

<Callout kind="info" collapsed="false">
  All data is synthetic and uses `DEMO-` identifiers. There are no real deliveries, credentials, or external services. Zeta is a safe simulation.
</Callout>

### Navigate the workspace

Use the Orders, Inventory, Exceptions, History, and Settings screens to inspect and manage the synthetic workspace. Press `F2` to cycle between the Management, Warehouse, and Shop views.

The global controls work as follows:

- **Search** filters synthetic order IDs.
- **State** filters orders by state.
- **+ Synthetic order** creates a new `DEMO-` order.
- **Lock** clears sensitive displays and pauses new work.

### Process your first order

<Steps>
  <Step title="Open the Orders screen" title-type="h3">
    Select a seeded order such as `DEMO-1001` to open its detail window.
  </Step>

  <Step title="Refresh the fixture observation" title-type="h3">
    Click **Refresh fixture observation** to get the latest synthetic marketplace data. Zeta checks whether the order is paid, supported, freshly observed, has a verified recipient, and is mapped to an exact item/model variant.
  </Step>

  <Step title="Reserve inventory" title-type="h3">
    Click **Reserve all lines**. Reservation is all-or-nothing: if any line lacks available stock, nothing is reserved. On success, units move from `AVAILABLE` to `RESERVED`.
  </Step>

  <Step title="Approve delivery" title-type="h3">
    Click **Approve manual delivery**. This moves the order to `QUEUED` but does not deliver anything.
  </Step>

  <Step title="Simulate the delivery outcome" title-type="h3">
    Choose a synthetic outcome: Confirmed, Rejected, Pending, Partial, Unknown, or CrashAfterEffect. Click **Simulate selected delivery outcome**. Each outcome changes the order and inventory state differently.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  For a full walkthrough of every order state, delivery outcome, and the reveal-and-attest flow, see the [Order Processing guide](/workflows/order-processing).
</Callout>

### Manage inventory

The Inventory screen shows available, reserved, quarantined, delivered, invalid, and total units for each product. Create synthetic products with names that start with `DEMO-`, import synthetic codes from text or CSV files, and map products to exact item/model variants. See [Inventory Management](/workflows/inventory-management) for details.

### Explore the warehouse view

Press `F2` to toggle the 3D warehouse view. Shelves show product stock, packages group around receiving, packing, review, and dispatch stations, and colors indicate order states. Click shelves, packages, or stations to navigate. Right-drag to pan and use the mouse wheel to zoom. See [Warehouse View](/workflows/warehouse-view) for the full control reference.

Press `F2` again to switch to the Shop view, which visualizes synthetic orders as arriving customers in a storefront. See [Shop View](/workflows/shop-view) for details.

### Handle exceptions

Some seeded orders demonstrate edge cases: `DEMO-1004` is unpaid and held, `DEMO-1006` is unsupported and held, `DEMO-1005` requests more stock than available and shows a shortage, and `DEMO-1008` uses an unmapped item/model. Uncertain delivery outcomes move orders to `REVIEW_REQUIRED` and quarantine units. See [Exceptions & Recovery](/workflows/exceptions-recovery) for the full workflow.

### Adjust settings

The Settings screen provides a fixture source online/offline toggle, reduced-motion mode, text scaling, encrypted snapshots and restore, interrupted-attempt recovery, and batch inspection. Offline mode permits local inspection and import, but refuses allocation, reveal, and delivery operations.

## Where data is stored

Normal Windows execution stores application data at:

```text
%LOCALAPPDATA%\Zeta\Synthetic-v1
```

The directory contains:

- SQLite database
- Ownership lock
- DPAPI-protected key file
- Application preferences
- Encrypted backups

The key file is protected for the current Windows user. Do not delete or replace it while the database is in use, because the application cannot decrypt existing inventory or backups without the original key material.

## Command-line options

Run the application with these options after the Godot project arguments:

- `--smoke-test`: Run the isolated end-to-end smoke test and exit.
- `--demo-preview`: Open a visual preview using an isolated temporary workspace.
- `--view=Warehouse|Shop|Inventory|Settings|History`: Select the initial application view.
- `--screenshot=<path>`: Capture the selected preview or application view to the specified path.

For example, launch directly into the inventory view:

```powershell
Godot --path src/Zeta.Godot -- --view=Inventory
```
